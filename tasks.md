# Лабораторные работы по параллельному программированию

Первые шесть лабораторных работ. Задания 3–6 последовательно развивают поисковый робот из задания 2.

## 1. Счётчик слов

В произвольном текстовом документе подсчитать, сколько раз встречается каждое слово, и вывести результат в консоль.

Требования:

- Использовать регулярные выражения (regexp).
- Корректно обрабатывать любые знаки препинания в любом количестве.

Текст для проверки можно сформировать генератором Lorem Ipsum.

## 2. Поисковый робот для исходного текста программы

Для Java-проекта в локальной папке построить обратный индекс наследования классов и вывести его в консоль. Для каждого класса найти и напечатать классы, для которых он является базовым (родительским).

Требования:

- Корректно обрабатывать ключевые слова `class`, `interface`, `extends`, `implements`.
- Использовать интерфейс `Map` и метод `getOrDefault()`.

Желательно использовать Stream API.

## 3. Поисковый робот с независимыми потоками

Усовершенствовать программу из задания 2: для обработки каждого файла исходного текста создавать отдельный поток (`Thread`). Взаимодействия потоков не требуется.

Требования:

- Дождаться завершения всех потоков. Можно использовать `join()`, желательно — `CountDownLatch`.
- Продемонстрировать работоспособность на большом проекте с GitHub, например Spring Framework.

## 4. Поисковый робот с синхронизацией доступа потоков к данным

Обрабатывать файлы исходного текста в отдельных потоках и собирать результат в единый индекс.

Требования:

- Для единого индекса использовать `Map`.
- Защитить доступ к индексу объектом синхронизации. Можно использовать `synchronized`, предпочтительно — `ReentrantLock`.
- Основной поток должен дождаться завершения всех потоков и только затем вывести единый индекс в консоль.

## 5. Поисковый робот с Executor Service

Усовершенствовать программу из задания 4: ограничить количество потоков, используя один из вариантов Java `ExecutorService`.

Требования:

- Формировать единый индекс с использованием `Future`.
- Собрать все объекты `Future` в список.
- Начинать считывать результаты через `get()` только после выдачи последнего задания на обработку.

## 6. Поисковый робот с Blocking Queue, реализующий Map-Reduce

Основной поток выдаёт задания на обработку файлов исходного текста фиксированному количеству потоков-исполнителей. Для передачи заданий и результатов, из которых собирается единый индекс, использовать `BlockingQueue`.

Порядок работы:

1. Создать две очереди и фиксированное количество потоков-исполнителей.
2. Основной поток отправляет задания в первую очередь.
3. Потоки-исполнители обрабатывают задания и помещают результаты во вторую очередь.
4. Основной поток забирает результаты из второй очереди и собирает единый индекс.
5. После выполнения всех выданных заданий основной поток выводит единый индекс в консоль.

Потоки можно не завершать либо завершать с помощью poison pill.
