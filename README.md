# omstu-parallel-6

Работы по предмету "Параллельное программирование" за 6 семестр ОмГТУ.

Реализована только лабораторная № 2 из [tasks.md](tasks.md): обратный индекс наследования классов и интерфейсов Java. Лабораторные № 3–6 пока не реализованы; они последовательно добавляют многопоточность к этому же роботу. Лабораторной № 1 с регулярными выражениями в коде нет.

## Запуск

Используется OpenJDK 27.0.0 из `mise.toml`. Все команды выполнять из корня репозитория:

```sh
mise trust
mise install
mise run lab2
```

По умолчанию программа читает `examples/project`. Для другой папки:

```sh
mise run lab2 /путь/к/Java-проекту
```

`mise run` без имени задачи тоже запускает лабораторную № 2 на примере. Сборка выполняется автоматически перед запуском. Все команды определены в [mise.toml](mise.toml), список с описаниями доступен через `mise tasks`.

Отдельная сборка: `mise run build`. Проверка: `mise run test`. Скрипты `build.sh`, `run.sh` и `run-spring.sh` заменены этими задачами. В `test.sh` остались только проверки.

## Запуск на Spring Framework

```sh
mise run spring
```

Задача скачивает [Spring Framework v7.0.9](https://github.com/spring-projects/spring-framework/tree/v7.0.9) в `build/spring-framework` и выводит индекс всех `.java`-файлов репозитория, включая тестовые исходники. При повторном запуске используется уже скачанная папка. Собирать Spring и устанавливать его зависимости не нужно.

Чтобы сохранить весь вывод:

```sh
mkdir -p build
mise run spring > build/spring-inheritance.txt
```

## Как работает программа

Вся реализация находится в [src/lab2/Main.java](src/lab2/Main.java):

1. `findJavaFiles` обходит папку и находит `.java`-файлы через Stream API.
2. `buildIndex` использует парсер из JDK, находит `class`, `interface`, `extends` и `implements` и собирает `Map<String, Set<String>>` с помощью `getOrDefault()`.
3. `simpleTypeName` извлекает имя родителя, убирая параметры типов и квалификатор пакета.
4. `main` выводит индекс. `TreeMap` и `TreeSet` обеспечивают сортировку и отсутствие повторов.

Для примера результат такой:

```text
Attachment ->
Base -> Attachment, Document
Document -> FeaturedDocument
FeaturedDocument ->
Identifiable -> Document
Readable -> Writable
Writable -> Document
```

Слева родитель, справа его непосредственные наследники. Если наследников нет, правая часть пустая. Вложенные классы тоже обходятся. Слова `class` и `extends` в строках и комментариях не создают ложных связей.

В индексе используются простые имена: `demo.Base` выводится как `Base`. Одноимённые типы из разных пакетов или областей объединяются. Анонимные классы, enum и record не добавляются как отдельные записи; неявное наследование от `Object` не учитывается.

Программа разбирает синтаксис исходников; зависимости анализируемого проекта устанавливать не требуется. Пустая папка даёт пустой результат.

## Что объяснять на защите лабораторной № 2

### Зачем нужен обратный индекс

В исходниках связь записана от ребёнка к родителю: `class Document extends Base<String>`. Робот разворачивает её: `Base -> Document`. Ключ `Map` — имя родителя, значение `Set` — имена его непосредственных наследников. Интерфейсы обрабатываются так же: `implements Writable` даёт `Writable -> Document`.

Индекс не вычисляет всех потомков по цепочке: у `Base` в примере нет `FeaturedDocument`, потому что тот непосредственно наследуется от `Document`.

### Как читать Main.java

1. `main` проверяет аргументы, выбирает папку, получает список файлов, строит индекс и выводит его. Допустим один необязательный аргумент — путь.
2. `findJavaFiles` рекурсивно обходит папку через `Files.walk`. `filter` оставляет обычные `.java`-файлы, `sorted` задаёт порядок, `toList` собирает результат. `try` с ресурсами закрывает поток обхода файловой системы. Stream API здесь последовательный: отдельных рабочих потоков нет.
3. `buildIndex` получает компилятор через `ToolProvider`, открывает файловый менеджер и создаёт `JavacTask`. Вызывается только `parse()`: он строит синтаксическое дерево, но не компилирует анализируемый проект в `.class` и не разрешает его зависимости. Поэтому нужен JDK, а сборка самого Spring не нужна.
4. `TreeScanner` обходит дерево. Его `visitClass` вызывается и для классов, и для интерфейсов. Проверка `Tree.Kind` исключает enum и record; пустое имя исключает анонимные классы. Вызов `super.visitClass` продолжает обход, в том числе внутри вложенных классов.
5. `putIfAbsent(child, new TreeSet<>())` создаёт запись даже для типа без наследников. Родители берутся из `getExtendsClause()` и `getImplementsClause()`. У интерфейса список расширяемых интерфейсов представлен в API дерева через `getImplementsClause()`, хотя в исходнике написано `extends`.
6. `simpleTypeName` снимает параметры типов и аннотации типа, затем оставляет часть имени после последней точки: `sample.Parent<String>` превращается в `Parent`.

Парсер отличает объявления от строк и комментариев. Строка `"class Fake extends Wrong {}"` не создаёт класс `Fake` в индексе.

### Как работает getOrDefault

```java
Set<String> children = index.getOrDefault(parent, new TreeSet<>());
children.add(child);
index.put(parent, children);
```

Если родитель уже есть, получаем его существующий набор наследников. Если его нет, получаем новый пустой набор. `getOrDefault` сам не добавляет отсутствующий ключ в `Map`, поэтому после `add` нужен `put`. При существующем ключе набор уже изменился по ссылке, а повторный `put` просто сохраняет тот же объект.

`TreeMap` сортирует родителей, `TreeSet` сортирует наследников и убирает повторы. Эти коллекции не обеспечивают синхронизацию; во второй лабораторной доступ к ним идёт из одного потока.

### Короткий рассказ о работе

«Программа рекурсивно находит Java-файлы и разбирает их парсером JDK. Я обхожу синтаксическое дерево, нахожу объявления классов и интерфейсов и для каждого явно указанного родителя добавляю имя ребёнка в обратный индекс. Индекс хранится в Map, значения получаю через getOrDefault. Для сортировки и удаления повторов использую TreeMap и TreeSet. После обработки всех файлов вывожу непосредственных наследников каждого типа».

Для демонстрации сначала запустить `mise run lab2`, сопоставить вывод с файлами в `examples/project`, затем показать `mise run test`. При необходимости продемонстрировать большой проект через `mise run spring`.

## Как задания № 3–6 развивают эту программу

Это план следующих работ, а не описание существующего кода.

- **№ 3 — независимые потоки.** На каждый файл создать отдельный `Thread`, внутри строить свой локальный индекс. Основной поток ждёт `CountDownLatch.await()`. Каждый рабочий поток вызывает `countDown()` в `finally`, чтобы ошибка не оставила ожидание навсегда. Общая изменяемая `Map` на этом этапе не требуется. Нужна демонстрация на большом проекте.
- **№ 4 — общий индекс и блокировка.** Потоки обрабатывают отдельные файлы и объединяют результаты в общей `Map` под `ReentrantLock`. Блокировку освобождать в `finally`. После ожидания всех потоков основной поток выводит единый индекс. Блокировка должна защищать всю операцию получения набора, добавления ребёнка и сохранения значения, а не только отдельный вызов `put`.
- **№ 5 — пул и Future.** Использовать `ExecutorService` с фиксированным количеством потоков. Задания возвращают локальные индексы; все `Future` складываются в список. Сначала выдать все задания, затем обходить список с `get()` и объединять результаты в основном потоке. Так общий индекс изменяется только в основном потоке и не требует блокировки. Если вызывать `get()` сразу после каждого `submit()`, задания будут фактически выполняться последовательно.
- **№ 6 — очереди и Map-Reduce.** Фиксированное число исполнителей берёт пути из первой `BlockingQueue`, разбирает файлы и помещает локальные результаты во вторую очередь. Основной поток собирает результаты и объединяет индекс. Разбор файла — Map, объединение — Reduce. Можно завершить исполнителей через poison pill: по одному сигналу на каждый поток. При ограниченных очередях нельзя допускать, чтобы основной поток застрял на отправке заданий, пока исполнители застряли на отправке результатов.

При добавлении потоков у каждого одновременно выполняющегося разбора должны быть свои `JavacTask`, файловый менеджер и локальные коллекции. Нельзя просто запустить текущий `TreeScanner` параллельно с одной общей `TreeMap` без защиты.

## Проверка

```sh
mise run test
```

Проверяется индекс примера, наследование нескольких интерфейсов, вложенные классы, параметры типов, имя родителя с пакетом, текст внутри строки, пустая папка, неверный путь и лишние аргументы.

Изменения делаются в отдельных ветках и предлагаются через pull request в `main`.
